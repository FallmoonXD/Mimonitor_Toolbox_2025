# 2025 款系统画面设置

显示器 OSD 与 Android 系统设置使用不同的画面菜单。只核对 OSD 会漏掉系统设置中的亮度、色彩、清晰度及专业设置。

本次直接通过 ADB 读取本机 `MiTVSettings.apk`、运行配置和原生参数，并对照 `PictureSettingsManagerImpl`、`SystemControlManager` 与 `TvConfigIdUtil` 的调用关系。截图不作为参数映射或功能支持的依据。

适用设备：`beekeeper`，固件 `OS3.0.109.0.UFFMAMN`。

## 界面分组与顺序

画面页按固件菜单整理为亮度、色彩、清晰度、专业设置，OSD 基础选项并入对应分组，保留原有信号限制。排序依据为本机通过 ADB 取得的 `MiTVSettings.apk`，以及 `DisplayDetailView`、`BrightnessView`、`ColorDetailView`、`SharpnessDetailView`、`ExpertDetailView` 的菜单构建顺序。

- **亮度**：背光、精密控光、对比度、黑色级别、黑色校正、对比度增强、局部对比度、HDR 色调映射。
- **色彩**：饱和度、色调、色温及 RGB、色彩增强、色域、色彩动态范围。色彩增强位于 RGB 后、色域前。
- **清晰度**：锐度、超分辨率增强、动态降噪、MPEG 降噪、平滑渐变。
- **专业设置**：Gamma、Gamma 偏移、当前白平衡点、色彩详细设定、灰阶响应时间。

Gamma 偏移改为一张卡片内的单行下拉选择，完整保留 -4 至 4 九档及原生枚举。之前为每五个按钮创建一张卡片，导致同一个标题重复两次；这不是两个独立参数。下拉选择也保留等待状态、原生回读确认、失败回退，界面刷新不会触发写入。

本次排序验证仅通过 ADB 读取 APK 哈希和当前原生参数，使用后台 Qt 控件核对菜单及交互，不打开设备菜单、不切换 Windows HDR 或 Dolby 输出。见 [界面排序验收](validation/2026-10-14-picture-layout.json)。

## 新增选项

| 工具箱选项 | 原生字段 | 对应关系 |
| --- | --- | --- |
| 色彩增强 | `g_video__vid_auto_color` | 关、低、中、高，对应 native 0、1、2、3；同步 `mitv.settings.db.video.color_booster` |
| Gamma | `g_video__vid_gamma_mode` 最低字节 | 0 为 2.2，1 为 BT1886；保留暗区增强及其他字节 |
| Gamma 偏移 | `g_disp__disp_gamma` | 标签 -4 至 4 对应 native 4、5、3、6、2、7、1、8、9 |
| 黑色校正 | `g_video__vid_black_stretch` | 关、低、中、高；与暗区增强是独立字段 |
| 对比度增强 | `g_video__vid_luma` | 关、低、中、高 |
| 局部对比度 | `g_video__vid_local_contrast` | 关、低、中、高；系统菜单禁用或隐藏的模式同样禁止调节 |
| 动态降噪 | `g_video__vid_3d_nr`、`g_video__vid_nr` | 两个字段同时写入并分别回读 |
| MPEG 降噪 | `g_video__vid_mpeg_nr` | 关、低、中、高 |
| 平滑渐变 | `g_video__vid_de_contour` | HDR、Dolby 四档可保存；SDR 游戏模式下仅显示状态 |
| 超分辨率增强 | `g_video__vid_aisr` | 关为 native 0，开为 native 2 |

写入先确认当前信号和原生模式，helper 检查模式是否发生变化；原生返回码与回读均通过后才同步设置数据库，再复核最终状态。失败时回退按钮显示。

色彩增强已加入预设和撤销快照，读取原生值，关闭值 0 也会保存。应用时放在所有模式切换及 PQ 重载之后；旧预设没有记录此项时跳过，不从数据库缓存猜测。其余系统高级选项尚未加入预设。刷新、查看 CMS 或当前白平衡点均不写参数。

## 校色与无效入口

- **色彩详细设定**：显示当前模式下七种颜色的色调、饱和度、亮度及启用状态。参数只读。
- **20 点白平衡**：显示开关、当前点与该点 RGB。只读取已选中的点，不扫描表格、不切换选择器、不执行重置。
- **色彩增强**：系统菜单称“颜色增强”。当前 `ColorDetailView` 直接调用 `setColorBooster`；旧 `AdvancedDisplayView` 的 CMS 冲突确认不能套用到所有入口。工具箱直接写此原生字段，不调用会同时改动其他算法的 `setAutoColorEnable`。写入前、原生写入后及数据库同步后核对 RGB、CMS 与当前白平衡点，参数不一致时报告失败。
- **平滑渐变**：虽然运行配置声明支持，SDR 游戏模式下写入低、中、高后仍回读为关。该模式仅显示状态，HDR、Dolby 游戏模式下四档通过回读。
- **AI 画质**：本机原生字段返回 -1，不提供有效开关。超分辨率强度、峰值亮度及动态清晰度也没有本机运行支持，不补入这些入口。
- HDMI/DP 模式、竞技模式及模拟屏幕尺寸会牵涉 EDID 或同步功能，继续使用显示器系统菜单；本次未增加这些入口。

原生字段回读确认接口状态，不能替代光学测量或证明每种图像算法的视觉效果。

## 恢复检查的更正

2026-10-13 OSD 测试结束时的 50 个原生字段和 112 个数据库字段核对覆盖当时的 **Dolby 模式**。SDR 的对照快照已包含受影响的色温和 RGB，HDR 未完成独立校色复核；该记录不能证明三种输入的颜色都已恢复。

2026-10-14 按用户既有校色档案分别恢复 SDR、HDR 和 Dolby 的自定义色温、RGB 及发生变化的 CMS 字段，随后再次切换三种输入复核。精密控光是共享状态，按已配置的 HDR/SDR 联动分别应用，不能假定它自动随模式回载。最后恢复原 Windows HDR 与 Dolby 输出。

完整验收摘要见 [系统画面与界面验证](validation/2026-10-14-system-picture-controls.json)。未重新进行仪器测色。

随后用户发现杜比的颜色增强仍开启。上面的既有校色档案没有记录 `g_video__vid_auto_color`，因此“校色记录无差异”没有证明此项符合用户要求；此前核对遗漏了这部分颜色状态。此次以用户已关闭后的新现场读数为基准，分别检查 SDR、HDR、Dolby 四档与输入回载，结束保留杜比关闭，不恢复之前开启的历史值。结果见 [色彩增强验证](validation/2026-10-14-color-enhancement.json)。
