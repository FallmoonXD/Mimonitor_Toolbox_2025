## 原生显示模式

旧代码混用了小米 `SceneMode` 与 MTK 原生枚举。根据此版固件的 `PictureSettingsManager` 常量及 `converSceneModeToXiaomi` 转换表，修正读取名称与写入编号。

**勘误：原生模式 13 是 Dolby Vision 游戏，原先标成自定义不准确；Dolby 自定义的原生编号是 61。** 模式 0 是有效的 SDR 自定义模式。

| 当前信号 | 界面选项与 MTK 原生编号 | 实机写入与最终回读 |
| --- | --- | --- |
| SDR | 标准 14、游戏 10、电影 9、自定义 0 | 四项通过 |
| HDR | 标准 15、游戏 16、电影 17、显示器 18、图片 19、Filmmaker 76 | 六项通过 |
| Dolby Vision | IQ 5、明亮 59、暗场 6、游戏 13、自定义 61 | 五项通过 |

切换仅允许在当前信号家族内进行。先读取原生模式及杜比标志，写入后验收返回码、目标模式和信号稳定性，再同步数据库并复核。页面、预设、托盘与快捷键使用同一套编号。无法取得有效信号时禁止模式写入。

## HDR 色调映射

2025 固件的 OSD 选项与偏移数组不一致，菜单名称不能可靠代表实际传给 MTK 的值。工具箱直接使用下面的原生值，OSD 缓存分别同步 MTK 与 UI 两套枚举。

| 选项 | MTK 值 | UI 值 | HDR 游戏模式 16 实测 |
| --- | --- | --- | --- |
| HGiG | 5 | 0 | native 返回 0，最终回读 5 |
| 层次 | 0 | 1 | native 返回 0，最终回读 0 |
| 动态 | 2 | 2 | native 返回 0，最终回读 2 |
| 明亮 | 1 | 3 | native 返回 0，最终回读 1 |

四档实机 Provider 返回均为 `-1`；保留“原生回读已确认”的独立警告，不将整个调用报告为无警告成功。此结果验证接口返回与生效读数，不代表光学测量了四种映射曲线。

Dolby 和 SDR 输入均已验证拒绝 HDR tone 写入。Dolby 页面显示当前为杜比并禁用 HDR 策略按钮，残留的 HDR 配置不能解释为杜比算法。未知值保留原始读数并清除旧高亮；实机 HDR Filmmaker 模式读到 tone 6，尚未为其命名。

## Windows 杜比联动

2026-10-17 补充：杜比偏好也可以保存在原生普通档和 320Hz 档，停用 PC 覆盖后仍可能输出 Dolby Vision。切换配置时保留 Windows 的选择，不将其误判为覆盖刷新失败。新的 25 项实际按钮场景、异常回滚及客户端退出恢复结果见 [v0.2.1 切换验收](validation/2026-10-17-release-0.2.1.json)。

| Windows HDR | Windows Dolby Vision | 实机原生状态 |
| --- | --- | --- |
| 开 | 开 | 模式 13，`g_dovi_info__=1` |
| 开 | 关 | 模式 16，`g_dovi_info__=0` |
| 关 | 关 | 模式 10，`g_dovi_info__=0` |

开关已实际切换并恢复。HDR 保持开启时，仅切换杜比开关即可改变显示器实际信号；因此工具箱持续读取原生信号，不能仅靠 Windows HDR 布尔值识别杜比。原生结果变化会刷新模式选项及画面数据，失效的旧连接或旧模式读取结果不应用。

Windows 的开关行为也见 [Microsoft HDR 设置说明](https://support.microsoft.com/en-us/windows/hardware/display-graphics/hdr-settings-in-windows)。工具箱识别此开关带来的信号变化，不负责安装或启用 Windows 杜比组件。

## 配置恢复与测试

脱敏结果：[2026-10-13 原生控制验证摘要](validation/2026-10-13-native-controls.json)。

- 测试前保存现场配置及各输入状态的原生/数据库读数，设备 helper 使用独立临时路径；测试时暂时退出官方工具箱，结束后恢复原启动方式。
- 各状态回到原模式后复核 50 个原生字段、112 个画质数据库字段，覆盖 RGB、CMS、背光、gamma、精密控光、当前 WB 点与自动色彩；最终恢复 Windows HDR、杜比开关和原画质参数。
- 首次备份覆盖 49 个原生字段，随后补充自动色彩到 50 项。最终只读审计与原始 49 项、112 个数据库字段一致；自动色彩按首次包含它的杜比状态现场备份恢复。
- 实测模式切换会改动自动色彩、色域缓存；数据库值与原生值可能不同。恢复时分别使用现场读数，不能只恢复菜单缓存。测试恢复过程据此补全，并在官方工具箱重启后再复核。
- 没有写 RGB、CMS 或 WB20 校色值，没有写 WB20 selector，没有扫描整张 20 点表。恢复已变动的自动色彩字段使用现场备份值。
- 官方版程序、PC 配置与启动项的 SHA256 前后一致。原生模式、HDR tone 和信号变化均通过实际 Python 控制器及新 Java helper 验证；界面选中项使用实机回读验证。
- 465 项本地测试通过，包含模式 0、跨信号拒绝、未知 tone、旧连接结果丢弃，以及预设原生写入未确认后停止剩余参数等回归场景。

字段复核不能替代完整校色备份、光学测量或设备重启持久性验收。

## 2026-10-14 系统画面与恢复修复

更正上一轮 OSD 测试的恢复范围：当时只完整核对当前 Dolby 模式，SDR、HDR 颜色有漏恢复。已按既有校色记录分别修复色温、RGB 与受影响的 CMS 字段，并复核三种输入的再次回载。

直接通过 ADB 核对完整系统画面菜单的资源、配置和底层接口，补充 Gamma、Gamma 偏移、黑色校正、对比度增强、降噪及超分辨率；CMS 与当前白平衡点保持只读。105 项原生参数逐档检查中，102 项通过，SDR 游戏模式的平滑渐变三档回读仍为关，已限制对应入口。系统菜单禁用或隐藏的模式限制同样保留。

实际窗口点击后的按钮待应用状态在 1.1–2.4 毫秒内更新，画面页完整刷新为 1.1–1.34 秒；设备写入回读仍需要约 4 秒，不将即时高亮当成已经写入成功。计时采样的是 Qt 控件状态，不是显示器扫描输出。487 项本地测试通过。

新版 standalone 已安装并启动，通过 Windows UI Automation 核对新增控件及当前 WB 点。随后用独立只读 getter 分别复核 SDR、HDR、Dolby 各 50 个原生字段与 112 个画质字段：校色记录无差异、读取不改变参数，已安装程序的精密控光联动为 SDR 0、HDR 2、Dolby 2。最终恢复 HDR 开、Dolby 开。详情见 [系统画面设置](2025-system-picture-settings.md) 与 [脱敏验收数据](validation/2026-10-14-system-picture-controls.json)。

### 色彩增强遗漏的更正

上述校色档案未记录自动色彩字段，不能由“校色记录无差异”推出色彩增强符合用户要求。此前将旧系统菜单的 CMS 冲突逻辑推广到当前菜单，错误地只提供了状态文字。

现新增色彩增强四档控制及预设原生值快照。写入不重载 PQ，前后核对 40 个 RGB、CMS、当前白平衡点字段；数据库同步后再次复核。实机验证及当前状态恢复结果见 [色彩增强验收](validation/2026-10-14-color-enhancement.json)。没有扫描或改写整张白平衡表，也未重新测色。
