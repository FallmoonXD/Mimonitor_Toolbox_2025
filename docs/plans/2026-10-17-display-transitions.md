# 下一阶段：减少杜比 PC 与 320Hz 切换时的黑屏

日期：2026-10-17。基于 v0.2.0 和本机 HDMI / FreeSync 开启的实测安排后续工作。

## 已确认的事实

- 无杜比 PC EDID 覆盖、工具箱完全退出时，普通档与 320Hz 档仍会恢复各自此前设置的 HDR 状态。
- 第一组：320Hz 档保存 HDR，普通档设置 SDR，再进入 320Hz 后恢复 HDR。
- 第二组：320Hz 档保存 SDR，普通档设置 HDR，再进入 320Hz 后恢复 SDR。Windows 实际输出与显示器原生输入读数一致。
- 原生普通档与竞技档提供不同的 EDID，本轮基块校验和分别为 FC 和 8B。以上结论限定于当前 Windows、显卡驱动、固件及连接，不能据此推断历史版本行为。
- 第一组在工具箱退出后丢失 ADB 连接，Windows 实际输出记录完整；第二组已重连 ADB，同时记录原生状态。
- 两组结束后已恢复兼容杜比 PC 配置、4K 159.975Hz、Dolby Vision、RGB 10 位。工具箱重新连接；69 项原生参数与发布验收快照一致，恢复及重启没有改动工具箱配置文件。

脱敏结果见 [HDR 档位记忆对照](../validation/2026-10-17-hdr-mode-memory.json)。原始逐次采样保留在本地 `.local/hdr_memory_20261017/`。

## 目标与行为约定

工具箱继续保持用户点击前的 HDR 开关状态：例如普通档 SDR 进入竞技模式，最终应为 SDR 320Hz，即使 Windows 自动恢复了该档此前的 HDR 状态。

仅操作选中的 XMI27B3 实体屏，保持其 FreeSync 状态、画面参数、ICC 和校色配置。刷新率以 CCD 实际目标时序为准，HDR 使用该屏实际 DXGI 色彩空间并结合显示器原生输入确认。`AdvancedColorEnabled` 可以在 SDR 下启用，不能单独当作 HDR 开关。

优先减少重复的信号重新协商。黑屏次数需要实测，不预先承诺固定一次；点击反馈耗时、实际完成耗时与肉眼黑屏次数分别记录。

## 1. 先修正 320Hz 切换流程

主要文件：`mimonitor_toolbox/dolby_pc.py`、`mimonitor_toolbox/adb.py`、`mimonitor_toolbox/windows_display.py`。

1. 切换前读取这台屏的 HDR 意图、实际输出、原生档位及返回普通档所需的模式。
2. 验证在当前固件下，能否直接在 HDR / Dolby 输入时切换原生 HDMI 档位。当前 ADB 接口有 SDR 限制，需要先核对固件实现并做有记录的实机比较，再调整此限制。
3. 触发必要的档位切换，等待 Windows 路径、目标时序列表和显示器输入稳定。
4. 重新读取 Windows 自动恢复的实际输出。HDR 与目标一致时跳过 setter；不一致时只修正该屏的 HDR。
5. HDR 稳定后检查实际时序。已经是目标 1080p 320Hz 或所保存的普通模式时，跳过重复设置；不匹配时再设置并回读。
6. 去掉“切档后一定仍为 SDR”的等待前提；根据目标输入与实际读数推进流程。

若实测直接切档不能稳定工作，SDR 中转保留为必要分支，并记录触发条件，避免无条件套用到所有情况。

## 2. 精简杜比 PC EDID 更新

主要文件：`mimonitor_toolbox/dolby_pc.py`、`assets/display/edid_profile.ps1`。

当前同时执行目标监视器 PnP 重枚举和 HDMI 档位切走再切回，另有 HDR 中转与重复时序设置。此前一次仅重枚举未生效，尚不能证明每次都需要全部步骤。

依次比较以下路径：

| 路径 | 要确认的内容 |
| --- | --- |
| 写入覆盖后，只重枚举目标监视器一次 | 能否稳定更新杜比能力，并得到正确的实际输入与时序 |
| 写入覆盖后，只执行一次有效的目标 HDMI 能力刷新 | 先检查固件广播处理，确认能否刷新当前档位而无需切走再切回 |
| 最小刷新后检查，失败才追加现有 HDMI 切档 | 保留必要的兼容处理，统计哪些状态真的需要追加操作 |

CRU 作者的常规操作是保存覆盖后重启显卡驱动，见 [官方说明](https://www.monitortests.com/forum/Thread-Custom-Resolution-Utility-CRU)。显卡驱动重启的范围大于单台监视器，本阶段优先使用目标屏接口；若需要对比整块显卡重启，应在实机测试安排中明确其对第二屏的影响。

“重新读取 EDID 能力”和“删除 Windows 历史显示配置”是不同操作。优化通过实际回读判断是否生效，保留 Windows 的显示配置记录。

## 3. 离线用例与实际按钮验证

先补能够覆盖本轮问题的用例：

- 热插拔后，Windows 恢复的 HDR 与切换前相反；控制器仍能得到用户要求的最终状态。
- 目标已匹配时不重复调用 HDR setter 和分辨率 setter。
- SDR 下高级色彩标志仍启用，实际 DXGI 与原生输入均为 SDR。
- EDID 最小刷新成功时不追加 HDMI 来回切档；仅在确认未生效后进入补救分支。
- 输入状态短暂滞后、路径重新出现及异常恢复，不提前报告成功。

然后使用候选程序的实际按钮验证：

| 验证项 | 关键覆盖 |
| --- | --- |
| 320Hz 开 / 关 | SDR、HDR、Dolby；缓存与目标一致及相反；普通档返回 |
| 杜比 PC 开 / 关 / 恢复原配置 | 普通档与竞技档；Windows HDR 开及关 |
| 重复点击当前状态 | 只核对状态，不重新连接显示器 |
| 工具箱重启 | 在 320Hz 下重启后仍可返回保存的普通模式 |
| 失败恢复 | EDID 更新失败、目标时序不可用、ADB 中断及输入确认超时 |
| 第二屏与画面配置 | 第二屏输出不变；各输入场景现场参数往返一致 |

保留现有恢复机制；显示器无信号倒计时为 30 秒，本机恢复看门狗为 16 秒无心跳触发。恢复路径也要读取热插拔后的实际状态，不能沿用“仍处于 SDR”等假定。

采样器应独立维持 ADB 传输，在工具箱退出导致连接消失时重新连接，避免本轮第一组的数据缺口。优先记录 ADB 原生输入、稳定标志、Windows 实际时序和色彩空间；肉眼黑屏次数在用户方便参与时确认。

## 本轮执行结果

- 直接 320Hz 切档已完成 SDR、HDR10、Dolby 及相反 HDR 缓存验证；匹配时跳过 HDR 和时序 setter，不匹配时修正一次。
- PC 配置采用 HDMI 能力刷新，跳过目标屏 PnP 重枚举；提交前读取 Windows 已加载的 EDID，随后交叉检查实际时序与原生输入。
- 已确认 Windows 在原生档位保存的杜比偏好是此前 PC 关闭误报的原因之一。实际输入跟随 Windows 的选择，工具箱不改写该偏好。
- 调试信号属性曾滞后于正常画面，改为原生丢信号查询及当前输入视频记录。读取中断会清除累计稳定状态。
- 25 项 Qt 实际按钮场景通过；客户端中断后独立恢复通过。69 项原生参数、配置、ICC、Gamma 和杜比偏好恢复一致。
- 初次 HDR10 320 尝试出现过一次超时并自动回滚，后续独立及矩阵复测通过，保留在验证记录的限制中。肉眼黑屏次数及第二块活动屏未在本轮完成实测。
