# Dolby Vision PC 与 320Hz 共存实测

2026-10-16，在红米 G Pro 27U 2025、OS3.0.109.0.UFFMAMN、HDMI1、FreeSync 开启的连接上完成兼容性试验，随后接入 v0.2.0 的正式按钮。下方记录最初的底层试验及正式操作流程。

## v0.2.0 正式操作

游戏页提供“杜比视界 PC”的“关”“开”和“恢复原配置”，按钮文字不附加括号说明。

- **开**：保留目标屏的原 EDID 覆盖键，启用兼容 320Hz 的 PC 杜比配置。
- **关**：停用 PC 杜比覆盖。HDR10 或 Dolby Vision 跟随 Windows 的杜比模式选择；原生档位也可能保存了杜比偏好。
- **恢复原配置**：还原接管前的覆盖，清除本功能的管理状态。如果正在 320Hz 模式，会同时恢复之前的普通分辨率。
- **320Hz竞技模式**：自动选择 Windows 1080p 320Hz，并确认实际目标时序；关闭时恢复进入前的分辨率。普通分辨率按目标屏单独记忆，重启工具箱后仍可返回。

这些操作保持 Windows HDR 开关原来的状态，不写 ICC 或校色参数。Windows 需已具备杜比支持、并在其 HDR 设置中启用杜比模式；此功能不安装系统杜比组件。当前要求 FreeSync 开启，仅适配已验证的固件和 HDMI 路径。

正式发布包已验证实际 319.975Hz Dolby Vision，以及工具箱重启后读取保存的普通模式并返回 4K 160Hz。普通档位和 320Hz 均保持 RGB 10 位，最后还原原 EDID 和用户配置，完整 69 项原生参数无差异。见 [正式包验收记录](validation/2026-10-16-release-0.2.0.json)。

EDID 操作由单独的管理员进程完成，日常调节不需要提升整个工具箱权限。Windows 侧验证失去心跳时恢复原 EDID，显示器本机则在 16 秒无心跳后恢复切换前 HDMI 档位。切换失败会核对恢复后的实际信号，不把桌面分辨率当作输出信号。断电会同时停止这两个进程，不能保证自动恢复；未完成的事务会阻止继续切换，需先核对并恢复保存的键。

## 2026-10-17：切换流程与 Windows 杜比偏好

- 320Hz 直接切换 HDMI 档位，随后读取实际时序、原生输入及 Windows HDR。只有结果不符合点击前的 HDR 状态或目标时序时，才补一次对应设置。
- PC 配置通过 HDMI 重新连接生效，省去额外的监视器 PnP 重枚举、无条件 SDR 中转及重复分辨率设置。提交前独立检查 Windows 设备节点已读到目标 EDID，再核对原生输入和实际时序。
- 原生普通档和竞技档的 Windows 杜比偏好可以独立于 PC 覆盖存在。本次对照将两档的 `HdrFlavor` 从 2 临时改为 1 后，停用覆盖得到普通 HDR；恢复为 2 后，同样没有 PC 覆盖也能输出 Dolby Vision。测试后恢复原值。工具箱不替用户改写这个偏好，也不再把这种杜比输入误判为覆盖刷新失败。
- `debug.signal.stable/unstable` 曾在画面正常时持续报不稳定。当前改用原生丢信号查询、当前输入视频记录和画面场景回读，交叉检查 Windows CCD 时序；读取中断会重新开始稳定确认。
- 点击后立即显示待应用状态和切换阶段，最终高亮仍以回读为准。

25 项实际按钮场景已验证，包含 SDR、HDR10、Dolby、双向档位记忆纠正、恢复原配置和两种故障注入。客户端在切档中退出后，独立看门狗先恢复注册表，再恢复 HDMI 档位，26.9 秒内回到 4K 160Hz Dolby；这不是连续黑屏时长。69 项参数、Windows 杜比偏好、ICC、Gamma 及配置文件均已复核恢复。见 [脱敏验收数据](validation/2026-10-17-release-0.2.1.json)。

以下 2026-10-16 记录保留当时的验证条件，其中固定的 SDR 中转和“停用覆盖必为普通 HDR”不再作为新流程的前提。

## 两种方案

| 路径 | 操作 | 实际结果 |
| --- | --- | --- |
| 方案 1：互斥 | 停用当前 PC 杜比 EDID 覆盖，切到 SDR，再开启 320Hz 档位 | 实际输出 1920×1080、319.975Hz，FreeSync 保持开启 |
| 方案 1：普通 HDR | 保持覆盖停用，更新 HDMI 能力后开启 Windows HDR | 3840×2160、159.975Hz，原生模式 16、杜比输入标志 0 |
| 方案 1：恢复 PC 杜比 | 恢复原覆盖和 Windows HDR | 回到原生杜比游戏模式 13、杜比输入标志 1 |
| 方案 2：共存 | 使用基于显示器原生 320Hz EDID 的候选覆盖，开启 Windows HDR，再选择 320Hz | 1920×1080、319.975Hz，原生杜比游戏模式 13、杜比输入标志 1 |
| 方案 2：返回普通档位 | 保留同一候选覆盖，返回普通 HDMI 档位及 4K 160Hz | 3840×2160、159.975Hz，Dolby Vision 正常识别 |

刷新率来自 Windows CCD 的实际目标时序，并同时检查显示器原生输入状态和信号稳定标志。共存状态连续采样一分钟，共 16 次；各次均为实际 319.975Hz、杜比输入开启、FreeSync 开启、稳定标志 1、不稳定标志 0。候选配置因此可以同时用于普通 4K 和 1080p 320Hz 档位，无需在两份覆盖之间反复切换。

## 候选配置如何得到

以这台显示器在 320Hz 档位实际提供的 EDID 为基础，保留其时序和 HDMI 能力数据，只将杜比厂商数据块替换为用户现有 PC 杜比配置中已能工作的数据块。处理扩展块计数，并重新计算校验和；没有编造新的 320Hz 时序。

两份杜比数据块有一个字节不同。本次只验证了复制已知有效数据块的结果，没有根据未公开的格式猜测该位的含义。

另外测试过在原 4K CRU 覆盖中追加 320Hz 扩展、紧凑合并扩展块、调整范围及 VRR 数据、替换 HDMI Forum 数据块等方法。这些候选仍只让 Windows 在竞技档位列出最高 120Hz。成功路径是从原生 320Hz EDID 出发，而不能只往原 4K 覆盖里加一条分辨率。

## 按钮需要处理的实际行为

2026-10-17 补充：在工具箱退出、杜比 PC 覆盖停用的两组遥控器对照中，普通档与 320Hz 档会恢复各自此前选择的 HDR 状态。以下“开启 HDR 后回到 120Hz”为之前一次试验的观测，尚不能据此认定每次 HDR 切换都必然降档，也不能把“重枚举后仍读到杜比”推广为每次都需要 HDMI 来回切档。见 [双向对照结果](validation/2026-10-17-hdr-mode-memory.json) 和 [下一阶段优化计划](plans/2026-10-17-display-transitions.md)。

- **Windows HDR 会改变刷新率。** 在 320Hz 下开启 HDR 后，Windows 先选成 1080p 120Hz；候选配置仍列出 320Hz，再次选择后才得到实际的 320Hz Dolby Vision。按钮需要在 HDR 切换完成后复核实际时序。
- **原生杜比状态有延迟。** Windows 模式切换刚返回时，原生值可能暂时仍是 SDR。首轮稳定性探针因过早读取而中止；随后改成等待原生杜比输入确认，再开始一分钟采样。不能把 setter 返回或一次即时读取当作切换完成。
- **高级色彩标志不能代替实际 HDR。** Windows 在换档后可能保留旧的 `AdvancedColorEnabled`，同时实际输出仍为 SDR。正式实现通过目标屏的 DXGI 色彩空间读取 HDR，并明确下发所需 HDR 状态；先确认 SDR 输出稳定，再启用 HDR，最后重选 320Hz。
- **Windows 会缓存 HDMI 能力。** 仅停用覆盖并重新枚举监视器，第一次仍识别为杜比；触发真实 HDMI 档位更新后，普通 HDR 才确认为模式 16、杜比输入关闭。互斥按钮也需要确认更新后的输入状态。
- **覆盖应只管理选中的实体屏。** 本次注册表及 Windows 模式操作均限定在 XMI27B3 的当前设备实例；后续实现不能用全局 HDR 或第二屏状态判断。

## 参数与恢复

每次试验都保存原覆盖键，再安装临时候选；试验结束后恢复原键。320Hz 探针在显示器本机安排恢复操作，短试验为 16 秒，持续采样使用 16 秒无心跳即恢复的看门狗，早于显示器 30 秒无信号倒计时。

共存状态下，除有意改变的 HDMI EDID 档位外，其余 68 项原生参数与本轮开工时的杜比参数一致。返回普通 4K Dolby Vision 后，完整 69 项也一致；返回 SDR 后，与本轮现场读取的 SDR 参数一致。

收尾恢复原 EDID 覆盖、Windows 4K 160Hz 和 HDR 开启，原生状态为 Dolby Vision；69 项原生参数及工具箱配置均与开工时一致。没有写入 ICC 或校色文件。工具箱恢复运行。

脱敏结果见 [原始数值与恢复核对](validation/2026-10-16-dolby-pc.json)。本次只验证上述实体屏、固件、显卡驱动和 HDMI 连接；未验证 FreeSync 关闭、DP/USB-C、重启后的持续性或长时间游戏负载。试验使用已有的 Windows 杜比组件，不包含为缺少组件的系统安装杜比支持。
