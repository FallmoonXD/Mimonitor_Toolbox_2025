# 调节响应优化

2026-10-16 完成调节响应优化，纳入 v0.2.0。

## 改动

- 在同一连接中复用显示器端 Java 进程，普通画面调节、RGB、系统画面选项、游戏功能及炫彩灯共用这一通道。预设与快捷键调用同一接口。
- 单项和批量读取使用独立请求回执，移除旧单项读取的 0.8 秒固定等待及 logcat 清空操作。
- 合并多项数据库同步和 PQ 刷新；这些命令仍由 ADB shell 执行，保留原有权限和顺序。
- 滑块提交延迟从 300 毫秒缩短到 120 毫秒，同一参数排队时只执行最新值；正在执行的调节正常完成，旧结果不会覆盖更新后的界面。
- 保留已检查写入的 250 毫秒稳定等待、原生回读、场景及杜比信号检查、色彩增强的 40 项校色检查，以及模式切换需要的等待。
- 修正色温数据库同步：此固件的 `picture_color_temperature` 保存转换后的 MTK 枚举，写入界面枚举会被系统观察器改回其他色温。自定义色温的数据库值为 0。
- FreeSync 根据当前 HDMI 档位选择原生值：普通档位关/开为 0/1，320Hz 档位为 2/3，避免固定写 3 顺带切换分辨率档位。DP/USB-C 仍为 0/1。

辅助进程只监听显示器本机回环地址，经独立 ADB 转发访问，每个连接使用随机令牌。空闲十分钟退出，断开或退出工具箱时主动关闭。发生结果不明的通讯中断时不自动重发写入；等待执行的请求还需客户端确认，已超时退出的请求不会随后执行。

耗时从界面请求到任务完成计算，包含通讯和回读，不是独立的面板响应测量。准星仍需实际切换/重新触发游戏场景，因此慢于普通参数。连续滑块实测请求 56、57、58 时只写入 56、58，最终回读 58，随后恢复原值。

每组测试恢复该组现场读取的参数；恢复 Windows HDR 和杜比开关后，再次比较开工时的 69 项原生参数，差异为零。恢复使用本次现场读数，没有套用旧校色导出文件。

最终安装目录的程序和 helper 哈希与构建产物一致。实际安装版自动连接成功，并通过无障碍接口点击精密控光“低”“中”，原生回读分别为 1、2。结束后 69 项原生参数及用户配置均与开工时一致，Windows 为 4K 160Hz、HDR 开启，显示器原生信号为 Dolby Vision。FreeSync 在现有普通档位下实际点击“开”，任务约 442 毫秒完成，档位仍为原生 EDID 3。

脱敏结果见 [本地安装验收](validation/2026-10-16-control-performance.json)。

## 320Hz 与 Windows 显示器配置

原实现固定写原生 EDID 6，并使用通用 PQ 刷新。固件 OSD 在 FreeSync 开启时选原生 EDID 5，关闭时选 6，随后向 TVPlayer 发送 `mitv.hdmi.action.EDID_VERSION_CHANGE`，通知值使用 Xiaomi 枚举。关闭竞技模式时，FreeSync 开启用原生 3，关闭用原生 1，但后者的通知值为 Xiaomi 2。

2026-10-16 完成同一台屏的对照测试：

| Windows EDID 配置 | 桌面模式 | 实际输出信号 | 1080p 可选最高刷新率 |
| --- | --- | --- | --- |
| 保留原 CRU 覆盖 | 1920×1080@120Hz | 3840×2160@120Hz | 120Hz |
| 临时停用覆盖并重枚举 | 1920×1080@320Hz | 1920×1080@319.975Hz | 320Hz |

四次采样均读取 CCD 实际目标时序；无覆盖时显示器信号稳定标志为 1、不稳定标志为 0。正式 Python 控制器的开启与关闭也实测通过，FreeSync 原生值始终为 1。此结果确认当前 CRU 覆盖阻止 Windows 使用显示器在竞技模式下提供的 320Hz 配置；只看桌面分辨率或 OSD 档位会误判。

测试前在显示器本机安排 16 秒后自动恢复 EDID，早于用户补充的 30 秒无信号倒计时，避免恢复依赖 ADB 持续在线。EDID 覆盖通过原键改名临时停用，测试后原样恢复；逐项比较覆盖值、工具箱配置及现场 69 项原生参数均无差异，最终为原来的 SDR、4K 160Hz。没有修改 ICC 或校色文件。

程序现已按 OSD 分支切换 HDMI 档位并发送专用通知。仅开启已实测的 HDMI SDR 路径；对目标屏检测到 EDID 覆盖时阻止开启并显示原因。检测只读所选显示器的注册表实例，不更改覆盖，也不根据第二屏的覆盖状态判断。开启的含义是切换显示器档位；Windows 仍需选择 1920×1080、320Hz。

脱敏证据见 [320Hz 对照测试](validation/2026-10-16-320hz-edid.json)。Windows 的 EDID 覆盖行为见 [Microsoft 驱动文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/overriding-monitor-edids)。

随后完成了 [Dolby Vision PC 与 320Hz 共存试验](2025-dolby-pc.md)，并接入 v0.2.0 正式按钮。兼容覆盖可同时输出实际 320Hz 与 Dolby Vision，并可返回 4K 160Hz Dolby Vision；未知覆盖仍然阻止开启。新控制器自动选择 Windows 分辨率，等待路径重新出现、输入稳定及原生回读，保留故障恢复。

正式 Qt 按钮完成 24 个操作用例，包括 320Hz 下的杜比开关、直接恢复原配置、Windows SDR 保持，以及两类注入失败后的恢复。重复选择已生效的 PC 杜比或 320Hz 状态约 0.65–0.73 秒完成核对，不重新连接显示器。SDR、HDR、Dolby 各自的现场参数在往返后保持一致；完整结果见 [v0.2.0 验收](validation/2026-10-16-release-0.2.0.json)。
